# AI assistant for the grading form editor

A teacher editing a matrix opens an assistant, picks course content for it to read, and
works out the grading form with it in a conversation. Each reply can propose a whole form,
which is shown as a preview. When the teacher is happy, the proposal is applied to the
editor as a draft.

## What the existing plugins show

### qbank_questiongen (ByCS)

[bycs-lp/moodle-qbank_questiongen](https://github.com/bycs-lp/moodle-qbank_questiongen)
generates questions from a topic, pasted text or course contents.

- **Choosing content:** a multi-select of the course's activities, filtered by
  `get_fast_modinfo()`, `$cm->uservisible` and `question_generator::is_cm_supported()`.
- **Extracting text:** `extract_content_from_cm()` per module type: page `content`, label
  `intro`, book chapters, lesson pages, folder files and resource files. Plain text, HTML and
  CSV files are read directly. PDFs and images are sent to an image-to-text model through
  `local_ai_manager`, and the result is cached by content hash
  (`qbank_questiongen_resource_cache`). Everything goes through `html_to_text()`.
- **AI:** one request per generation, in an ad-hoc task, with a hard dependency on
  `local_ai_manager`.

### local_sqlchat

[marcusgreen/moodle-local_sqlchat](https://github.com/marcusgreen/moodle-local_sqlchat)
turns questions into SQL and supports refining it in a conversation.

- **The caller owns the conversation.** `api::generate_sql($question, $contextid,
  $extrarules, $history)` keeps no state; the caller passes the earlier turns each time.
- **History is bounded.** `chat_engine::build_history_block()` sends only the last 3 turns,
  truncates each one, and labels them "oldest first — resolve references like *that*,
  *also*, *instead* against these turns; ignore them if the question starts something new".
  None of the backends take a message array, so every turn is resent as text.
- **Validate, then repair once.** The SQL is validated and dry-run. On failure the error is
  sent back to the model for one repair attempt before the user sees an error.
- **Caller rules.** `$extrarules` is appended to the prompt's rules, so a caller can add its
  own conventions without the engine knowing about them.
- **Backend choice without dependencies.** `llm_bridge` supports core AI, `local_ai_manager`
  and `tool_aimanager`, and falls back to core AI when the configured plugin is missing.
  Core AI is reached through `\core\di::get(\core_ai\manager::class)`, so tests can replace it.
- **Debugging aid.** An optional setting shows the prompt that was sent.

### Moodle core AI (5.2)

- `\core_ai\aiactions\generate_text` takes only `prompttext`, so a conversation must be
  packed into one prompt.
- The system instruction is a site-wide provider setting, so the plugin's own instructions
  go in the prompt too.
- Core handles policy acceptance (`core_ai/policy`), whether the action is enabled in the
  context, rate limiting, and logging and privacy of each request.

## Design

### The proposal is the export format

Each reply that proposes a form contains one fenced JSON block in the plugin's export
format (`definition_exporter`). The server:

1. extracts the block,
2. validates it with `definition_importer`,
3. renders it with the matrix renderer in preview mode.

Applying it goes through `import_definition()`, which saves a draft and is refused once the
form has been used for grading. So nothing the model writes reaches the page or the
database without the same validation and escaping as an imported file. This is the main
defence against instructions hidden in course content.

The parser sets `formatversion` itself and drops `options` and `files`: the model may not
change display options or add files. Descriptions are treated as Markdown.

### Conversation

Following sqlchat, the browser keeps the conversation and sends the state with each turn:

- the selected sources (course module ids),
- the earlier turns (the teacher's instruction and the model's short reply), capped to the
  last 4 and truncated,
- the current proposal as JSON, so "make criterion 2 stricter" edits it instead of
  starting again,
- the new instruction.

The first turn starts from the saved form when there is one. If the reply's JSON fails
validation, the error is sent back for one repair attempt, as sqlchat does with SQL.

### Sources

Adapted from questiongen:

- The description of the activity being graded is always offered and selected by default.
- Pages, labels, books, lessons, folders and resources with text, HTML or CSV files.
- Only modules that are `uservisible` to the teacher.
- Each source is truncated, and the total is capped (default 20,000 characters), so the
  prompt cannot grow without limit. The panel shows the size of what is selected.
- PDFs and images need image-to-text, which core AI does not offer. They are left out of
  version 1 (see Decisions).

### Backends

`ai\backend` is an interface with one call, send a prompt and return text. The default
implementation uses core AI. Following sqlchat, it can also use `local_ai_manager` or
`tool_aimanager` when installed, falling back to core AI otherwise, so there is no hard
dependency. A fake implementation drives the tests.

### UI

An **AI assistant** button next to Import and Export on the edit page opens a panel:

```
┌ Sources ─────────────┬ Conversation ──────────────┬ Preview ───────────────┐
│ ☑ Assignment brief   │ You: 4 criteria, 3 levels, │ [rendered matrix]      │
│ ☐ Week 1 (Page)      │      focus on evidence     │                        │
│ ☑ Essay guide (Book) │ AI: Here's a draft…        │ [Apply as draft]       │
│ ~6,200 / 20,000 chars│ [ instruction    ][Send]   │ [Discard]              │
└──────────────────────┴────────────────────────────┴────────────────────────┘
```

AMD modules, as recommended for 5.2 in [ui-guidance-research.md](ui-guidance-research.md).
New replies are announced in a live region, focus moves predictably, and a busy state is
shown while a request is running.

## Where the code goes

Method-neutral parts go in `classes/local/framework/ai/`, ready for the library plugin
(see [library-split.md](library-split.md)):

| Class | Job |
|---|---|
| `backend` | Interface: send a prompt, get text back |
| `llm_backend` | Core AI by default; `local_ai_manager` or `tool_aimanager` when installed |
| `content_source` | List the course's readable modules and extract their text |
| `prompt_builder` | Instructions, export format, sources, history, current proposal and method rules |
| `reply_parser` | Split a reply into message and proposal, and validate the proposal |
| `assistant` | One turn: build the prompt, call the backend, parse, repair once |

Matrix-specific parts: the method rules passed to `prompt_builder` (scored levels, Markdown
allowed), the web services, the capability, the AMD module and templates, and the strings.

## Security and privacy

- **Access:** `require_login`, `moodle/grade:managegradingforms` and a new
  `gradingform/matrix:useaiassistant` capability, so sites can turn it off for some roles.
- **AI availability:** the button only appears when `generate_text` is enabled in the
  context, and the core policy modal is shown before first use.
- **Course content:** only modules visible to the teacher. Sources are wrapped in clearly
  marked blocks, and the prompt tells the model to treat them as material, not
  instructions.
- **Output:** validated JSON only, rendered and saved through the existing escaped paths.
- **Privacy:** version 1 stores no conversation (it lives in the browser). Core records each
  AI request and covers it in its own privacy provider.

## Phases

1. **Backend, with tests.** `backend`, `llm_backend`, `content_source`, `prompt_builder`,
   `reply_parser` and `assistant`, tested with a fake backend and a mocked core AI manager.
2. **Web services.** List sources, run a turn (returns the message, the proposal and the
   preview HTML), and apply a proposal as a draft.
3. **UI.** The panel, policy modal, accessibility and busy state.
4. **Hardening.** Capability, settings (backend, size limit, show prompt), Behat with the
   fake backend, privacy metadata, and docs.

## Decisions

1. **PDFs and images:** left out of version 1. Later options: use `local_ai_manager`'s
   image-to-text when installed (as questiongen does), or an external text extractor.
2. **Keeping conversations:** in the browser only for version 1. Storing them per user and
   form would let teachers resume, but needs a table and privacy support.
3. **Where it lives:** inside matrix, under `local/framework/ai`, until the library plugin
   is extracted.
4. **UI technology:** AMD for 5.2.

5. **AI availability in an activity:** an activity's saved AI settings only list the course assistance actions
   (`summarise_text`, `explain_text`), never `generate_text`, so `is_action_enabled_in_context()` always says no
   once they are saved. `llm_backend` therefore checks the course and activity "AI tools" switches instead. Worth
   raising with Moodle HQ, because any plugin that uses `generate_text` in an activity hits the same problem.
